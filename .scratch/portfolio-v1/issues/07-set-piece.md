# 07: The Set-Piece

**What to build:** The one moment of genuine delight on the site.
A reader picks a Source and the whole page takes its colour from it, which makes this site an instance of the idea behind `omarchy-liquid-glass-theme` rather than a container describing it.

There is at most one Set-Piece per screen and this is it.
The moving light source from prototype variant C is explicitly **not** built.

**Blocked by:** 04, 05.

**Status:** done

- [x] Sources are content, so adding one is a content change and not a code change.
- [x] Choosing a Source updates the palette custom properties on the document root. No re-render, no layout shift.
- [x] The page recolours and **Restrained Clay still reads as clay** under every Source, because saturation and lightness never came from the Source.
- [x] The Source canvas is decorative to assistive technology; the Source controls are labelled and keyboard operable.
- [x] Under `prefers-reduced-motion`, the palette changes without transition and the Set-Piece still works.
- [x] This island is the only JavaScript on the route, and the initial-route JS budget is still met. If it is not, the Set-Piece loses, per ADR-0001.
- [x] The Floor harness stays green.

## Comments

Implemented as a React island, `src/components/SetPiece.tsx`, mounted once in `src/pages/index.astro`'s new "Source" bento cell with `client:idle={{ timeout: 1000 }}` - hydration piggybacks on browser idle time so it never competes with the critical rendering path, bounded to 1s so it can't be starved indefinitely on a busy main thread. `@astrojs/react`, `react`, and `react-dom` were added to the project; this is the first island of any kind in the codebase, per the spec's "React islands only where interaction requires them."

Sources are a fifth content collection, `src/content/sources/*.md` (schema in `src/content/schemas.ts`: `label`, `image`, `order`), six entries shipped as small abstract-gradient SVGs under `public/sources/`, colour stops carried forward from the prototype's own `SOURCES` list (`prototypes/set-piece.prototype.html`, branch `prototype/set-piece`) for continuity with the decision record in ADR-0002. Adding a seventh Source is one new Markdown file plus one new SVG, no code change, per the ticket's first line item.

Selecting a Source draws its image onto a small (96x64) canvas, reads the pixels straight back out with `getImageData`, and passes that `Uint8ClampedArray` directly into `derivePalette` (ticket 04) - the exact contract that module's Vitest suite already holds to its invariants, unchanged by this ticket. The result is written onto `documentElement.style` as seven custom properties (`--color-ground` etc.) via `setProperty`, which is what makes this "no re-render, no layout shift": nothing about the DOM tree changes, only the values the existing Tailwind `@theme` custom properties resolve to at paint time, so every `bg-ground`/`text-ink`/`clay` utility already on the page picks up the new hue for free. The same path runs once on mount for the pre-selected default Source too (a `useEffect` calling the same `selectSource` a click would), rather than trusting that `global.css`'s static hue-22 default happens to match whatever hue "Copper dusk"'s actual pixels sample to - that trust was never enforced or tested, and the code review below is what surfaced it. Verified visually with `agent-browser`: clicking through all six Sources recolours the whole page instantly with no flash of unstyled content and no layout shift, and Restrained Clay's extrusion and Carve both keep reading correctly at every hue, exactly as ADR-0002's invariants promise.

The canvas is `aria-hidden="true"` (decorative, matches the ticket's wording exactly); the Source buttons carry their own visible text label ("Copper dusk", "Oxblood", ...) rather than a background-image thumbnail, which doubles as their accessible name with no extra `aria-label` needed. Keyboard operability comes for free from using real `<button>` elements; the existing `clay-pressable` utility (ticket 03) supplies both the baseline physical press response Fun requires and the `:focus-visible` outline the keyboard-focus Floor test already checks generically. Selected-state is a Tailwind `aria-pressed:` variant reusing the same accent-outline treatment, no new CSS.

The "Source" bento cell sits third, right after Experience, not between Hero and Experience: tickets 05 and 06 both established and reaffirmed "Hero, Experience, ..." as the fixed priority order (Experience is the only third-party validation besides the Liquid Glass stars, per the spec, and is what the Secondary Reader looks for first), and an earlier draft of this ticket broke that silently by inserting Source ahead of Experience. Caught by the Standards review below.

Three defects were caught by measurement and review, not by inspection alone, and all three are the kind the spec warned this ticket about:

1. The first version gave every swatch button a `background-image` thumbnail of its Source, set inline via SSR'd `style`, so the browser fetched all six images immediately on page load rather than on selection. Under Lighthouse's simulated throttled-4G profile this pushed LCP to 2030ms, over budget. Per this ticket's own line item ("If it is not, the Set-Piece loses, per ADR-0001"), the thumbnails were cut; swatches are now text-label pills and only the selected Source's one image is ever fetched, on click (plus, since the mount-time fix above, the default's). LCP is 1500-1950ms across many repeated runs, comfortably under the 2.0s budget.
2. `scripts/floor/bundle-size.mjs` (ticket 02) only ever scanned `<script src>` and `<link rel="modulepreload">` in the served HTML. An Astro island's own code is neither: the `astro-island` custom element carries `component-url`/`renderer-url` attributes and loads both via a runtime dynamic `import()`, so the existing script silently reported 0KB for this island the first time it was measured. Fixed to discover those two attributes and then follow every local `import`/`from` specifier in each chunk transitively (react.js is imported by both the renderer and the component chunk), so the real payload - `client.js` (React's runtime, ~56KB gzip), `react.js` (~2.8KB), and `SetPiece.js` (~1.4KB), ~60.2KB total - is what the budget actually checks now. This was a real gap in the Floor harness ticket 02 built for a zero-JS site, not something specific to this island; it would have silently let any future island ship unmeasured.
3. The Set-Piece Playwright spec is the first Floor assertion with a real fetch-decode-hydrate chain behind it (previous specs only ever inspected already-served static HTML). Under load, a test could click a Source before hydration had actually attached the click handler, or capture its "before" colour before the island's own mount-time default-Source draw had settled - a genuine race, not just a slow machine, since a late-resolving mount-time draw could silently overwrite whatever the test's own click had just applied. The Spec review below caught this directly: `npm run test:floor` run a few times in a row still failed intermittently even after `playwright.config.ts` was first pinned to `workers: 2`. Fixed properly rather than by widening timeouts further: `tests/floor/support.ts` adds `waitForSetPieceReady`, which polls for both the `astro-island`'s `ssr` attribute being gone (hydrated) and the canvas having actually been drawn to (the mount-time `derivePalette` call has resolved) before a test reads or clicks anything. Confirmed by running `npm run test:floor` three times concurrently against the same build (24 Playwright assertions plus three simultaneous Lighthouse passes) with zero failures, which is a harder stress test than any single sequential run could produce.

Two new Playwright specs: `tests/floor/set-piece.spec.ts` covers the Testing Decisions' Seam 2 assertion verbatim ("Choosing a Source changes the accent custom property on the document root") plus the canvas/labelling/keyboard-operability line item; one assertion was added to the existing `tests/floor/reduced-motion.spec.ts` confirming a Source selection still recolours the page inside a `reducedMotion: 'reduce'` context, since the ticket calls out "the Set-Piece still works" under reduced motion specifically, not just "nothing animates" (already covered by that file's existing blanket check, since `global.css` never puts a transition on colour or the custom properties themselves - only `clay-pressable`'s `box-shadow`/`transform`, and only under the `no-preference` media query already). Both specs share `waitForSetPieceReady` and an `accentColor` helper from the new `tests/floor/support.ts` rather than each redefining the same inline colour-reading closure.

`npm run typecheck`, `npm run test` (48 Vitest assertions, ticket 04's suite, unchanged by this ticket), and `npm run test:floor` (bundle size, Lighthouse, all 8 Playwright specs) pass, repeated five times sequentially and three times concurrently: Lighthouse accessibility 100 and LCP 1500-1950ms every run, ~60.2KB gzipped initial-route JS against the 100KB budget.

Reviewed with `/code-review` (Standards and Spec axes, both against `main`). Standards found one hard violation (the bento cell ordering above) and three judgement calls, all applied: `@types/react`/`@types/react-dom` moved from `dependencies` to `devDependencies` in `package.json` to match this file's own existing categorisation; the token-name array in `SetPiece.tsx` simplified from an `Object.keys(...) satisfies Record<...>` construction to a plain literal, matching the convention `derive-palette.test.ts` already established; the duplicated inline `accent()` closure across the two Floor specs extracted into shared `tests/floor/support.ts`. Spec found one real defect (the intermittent Floor-harness failure above, directly contradicting an earlier draft of this Comments section that claimed "zero failures" after only the `workers: 2` change) and one implementation gap (the default Source never actually ran through `derivePalette`), both fixed above; the two flagged "scope creep" items (`scripts/floor/bundle-size.mjs` and `playwright.config.ts`) were judged defensible given the ticket's own explicit budget line item and are unchanged in kind, though the harness fix now goes further than `workers: 2` alone for the reason given in defect 3.
